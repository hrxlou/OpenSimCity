# 시뮬레이션 핵심 계약

이 문서는 시스템 구현 전에 순환 의존과 결과 해석을 고정한다. 수치와 밸런스는 테스트 fixture로 조정하되 입력·출력 의미는 임의로 바꾸지 않는다.

## 1. 도시 성장의 최소 인과관계

```text
외부 연결
  -> 이주 가능 인구와 외부 시장
  -> 주택 입주와 일자리 충원
  -> 통근·상품 이동
  -> 가구 소비와 사업체 가동률
  -> 세수와 서비스 지출
  -> RCI 시장 압력
  -> 필지별 개발·쇠퇴
```

외부 연결이 없는 도시는 기존 내부 활동을 유지할 수 있지만 신규 이주, 수출입, 외부 통근을 만들지 못한다. 도로에 단순히 접하는 것과 유효한 네트워크에 연결되는 것을 구분한다.

## 2. 수요의 세 단계

### 도시 전체 시장 압력

- 주거: 빈 일자리, 실업률, 빈집률, 세율, 도시 매력도
- 상업: 소비력, 상품 공급, 빈 점포, 노동력, 세율
- 산업: 일자리 필요, 노동력, 상품 부족, 외부 시장 접근, 세율

결과는 용도별 `-1..1` 범위로 정규화하고 월별 평활화와 최소 유지 기간을 둔다.

### 필지별 입지 적합도

도로 도달성, 통근시간, 오염, 소음, 토지가치, 서비스, 인접 용도를 입력으로 한다. 도시 전체 수요가 높아도 부적합한 필지는 개발하지 않는다.

P5 교통 전에는 통근시간을 미리 구현하지 않는다. P2 도로 그래프가 외부 연결까지의 결정적 정수 거리인 `NetworkDistanceToExternalGate`와 거리 band를 제공하고, P3 개발 시스템이 이를 용도별 약한 입지 factor로 사용한다. 도달 불가는 개발 자격을 막지만, 도달 가능한 필지의 거리는 단독으로 개발 여부를 결정하지 않는다. P5 이후 실제 통행·혼잡 비용이 준비되면 같은 접근성 query 계약을 확장한다.

### 개발 실행 가능성

도시 수요, 입지 적합도, 비어 있는 적법한 필지, 전력·수도, 성장 cap, 건설 중인 공급을 함께 확인한다. 후보는 안정적으로 정렬한 뒤 시스템 전용 RNG로 제한 수만 샘플링한다.

## 3. 인구·고용·이주

MVP는 개별 시민 대신 건물 또는 권역 단위 코호트를 사용한다.

```text
Population cohort: 인원, 노동 가능 인원, 교육/소득 tier, 주거 건물
Employment bucket: 용도/교육 tier, 총 일자리, 충원 일자리, 접근 가능 권역
Migration flow: 유입 후보, 유출 후보, 실제 이동량, 원인
```

일자리 충원은 안정 ID 순서의 권역별 집계 매칭으로 시작한다. 완전한 경로 비용은 교통 Phase에서 추가하되, 그 전에도 같은 외부 연결 컴포넌트 안에 있는지 확인한다.

## 4. 공공 재정과 민간경제

`MunicipalFinanceState`는 플레이어의 시 재정만 관리한다. 세입, 서비스·도로 유지비, 건설비, 대출이 여기에 속한다.

`UrbanEconomyState`는 가구와 사업체의 집계 상태를 관리한다. 소비력, 상품 공급, 사업체 가동률, 고용이 여기에 속한다. MVP에서는 개별 계좌 대신 정규화된 지수와 수량을 사용한다.

두 상태는 세율과 세수로 연결되지만 같은 원장을 공유하지 않는다.

## 5. 시간과 결정성

- 도시 명령은 `(SimulationTick, CommandSequence)`로 완전히 정렬한다.
- 일시정지, 배속, 저장 요청은 도시 명령이 아닌 Application control이다.
- 시스템마다 독립 RNG 상태를 갖고 저장 스냅샷에 포함한다.
- `Dictionary`와 `HashSet`의 열거 순서를 결과 계산에 사용하지 않는다.
- 후보와 이벤트는 안정 ID 또는 셀의 row-major 순서로 정렬한다.
- 부족한 전력·서비스의 배분 우선순위도 안정 ID로 결정한다.
- 시스템별 다음 실행 tick과 미처리 event queue를 저장한다.

크로스 플랫폼 결정성이 필요한 계산은 정수 또는 명시적으로 양자화한 값을 우선한다. 부동소수점 통계는 테스트에 허용 오차를 명시한다.

## 6. 서비스 거리

- 공간 필드: 공원, 소음, 오염, 일부 토지가치 효과
- 도로 이동시간: 소방, 경찰 출동, 병원, 폐기물 수거
- 거리와 수용량: 학교, 통신 등 정기 서비스

표시 차량은 서비스 결과를 만들지 않는다. 시뮬레이션이 계산한 출동·통행 결과를 샘플링해 보여준다.

## 7. 기간 경계

일·월 단위 시스템은 기간 시작 스냅샷을 읽고 기간 종료에 결과를 제출한다. 같은 월에 새로 성장한 건물이 그 월 전체의 세금이나 소비를 소급 생성하지 않는다. UI는 결과가 어느 기간의 값인지 표시할 수 있어야 한다.

## 8. 플레이어 경험 게이트

기능의 정확성·결정성 gate와 플레이어가 문제를 이해하고 수정할 수 있는 experience gate를 함께 관리한다. 공통 증거 형식, 단계별 최소 경험, P3 접근성 근사는 [플레이어 경험 게이트 계약](PLAYER_EXPERIENCE_CONTRACTS.md)을 따른다.
