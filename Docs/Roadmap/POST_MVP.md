# Post-MVP 후보와 진입 조건

이 문서는 P0~P9 첫 출시 gate를 통과하기 전에 기능 목록을 다시 비대하게 만들지 않도록 후속 후보와 착수 조건을 기록한다. 아래 항목은 현재 Phase gate의 필수 조건이 아니며, 선행 experience evidence가 없으면 GitHub 실행 이슈로 승격하지 않는다.

## F-01 마일스톤·순차 해금

### 진입 조건

- P3~P7의 각 핵심 기능이 공개 UI와 회복 시나리오를 가진다.
- P9 첫 15분 onboarding에서 실제로 어려운 소개 순서가 기록된다.
- 해금 없이도 각 기능이 독립적으로 재미와 trade-off를 제공한다.

### 최소 수직 슬라이스

- 인구와 지속 기간처럼 공개되고 안정적인 조건을 사용한 3단계 순차 해금
- 영구 양자택일이 아니라 무엇을 먼저 해금할지 선택하는 한 번의 분기
- 현재 진행도, 다음 조건, 새 도구 소개

### 금지

- 데이터맵·원인 UI·철거·기본 복구 수단 잠금
- 평균 행복도나 `교통 문제 해결`처럼 원인과 판정이 불투명한 단일 조건
- 검증되지 않은 후속 기능을 보상 슬롯으로 미리 고정

## F-02 서비스 시설 업그레이드 한 종류

### 진입 조건

- P7 서비스 배치가 공간 선택과 용량 trade-off를 제공한다.
- 새 시설 추가와 기존 시설 증설이 서로 다른 실행 가능한 선택이 될 수 있다.

### 최소 수직 슬라이스

- 시설 한 종류와 upgrade 한 개만 선택한다. 예: 소방서 차고 증설
- stable upgrade state, command, 비용, 용량 입력, 시각 상태, 저장 왕복
- 업그레이드가 서비스 결과를 직접 쓰지 않고 기존 용량·지연 입력을 바꾼다.

### 금지

- 서비스 5종에 업그레이드 3개씩 동시 추가
- 한 시설 무한 증설로 공간 배치가 무의미해지는 밸런스

## F-03 시그니처 건물 한 종류

### 진입 조건

- P7 특성화가 일반 도시와 다른 실행 가능한 운영을 제공한다.
- 해금 목표가 단순 인구 반복이 아니라 해당 운영의 성취를 측정한다.

### 최소 수직 슬라이스

- 특성화와 연결된 시그니처 건물 한 개
- 공개된 해금 진행도와 placement command
- 기존 서비스·수용량·방문·생산 입력을 통한 효과
- placeholder로 경험을 먼저 검증하고 production 고유 아트는 이후 승인한다.

### 금지

- 수요·토지가치·행복도를 이유 없이 직접 올리는 전역 버프
- gameplay 검증 전에 여러 랜드마크와 고유 아트를 제작

## F-04 data-only 콘텐츠 팩

### 진입 조건

- P9 built-in content catalog, definition validator, save content version 정책이 안정적이다.
- 누락 definition의 명시적 오류 또는 안전한 fallback이 검증된다.

### 최소 수직 슬라이스

- 코드 실행 없는 건물 또는 도로 definition pack 한 종류
- manifest/version/dependency 검증과 호환성 메시지
- 저장 파일이 요구하는 content ID 목록과 비활성화 시 동작

### 금지

- 초기 공개 코드 모드 API
- Steam Workshop 또는 플랫폼별 배포 통합
- 내부 타입을 그대로 노출하고 하위 호환성을 약속하는 scripting surface

## 별도 근거가 생기기 전 제외

- 자유곡선 도로, 교량·터널·입체교차로
- 차선별 차량 AI와 신호 주기 편집
- 모든 시민의 일정과 탑승 상태
- 지하철·철도·트램·택시 동시 구현
- 실시간 지형 변형
- 혼합용도·오피스 존: 인구·고용·상품 모델에서 기존 RCI와 다른 선택을 만든다는 fixture가 먼저 필요하다.
